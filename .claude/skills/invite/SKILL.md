# รหัสเชิญและผู้ใช้ของ KeviN

เจ้าของเรียกใช้ตอนอยากเพิ่มคนเข้าระบบ · **ทำผ่าน Supabase MCP ทั้งหมด ไม่ต้องให้เจ้าของ
ไปเปิด SQL Editor เอง** เว้นแต่ MCP ต่อไม่ติด

พื้นหลังทั้งหมดอยู่ใน `doc/DECISIONS.md` หัวข้อ "เปิดให้ใช้หลายคน — 8 ก.ย. 2026"

## กติกาที่ห้ามลืม

- **รหัสใช้ได้ครั้งเดียว** · "ถูกใช้แล้ว" = `used_by` ไม่เป็น null
- **รหัสถูกเผาตอนกดสมัคร ไม่ใช่ตอนยืนยันอีเมล** — สมัครแล้วอีเมลผิดก็เสียใบหนึ่ง
- **ลบบัญชีทิ้ง แล้วรหัสกลับมาว่างเอง** (`used_by` เป็น `on delete set null`) ไม่ต้องปลดด้วยมือ
- **`invite_codes` เปิด RLS แล้วไม่มี policy สักข้อ** = แอปอ่านไม่ได้เลยโดยตั้งใจ
  · MCP ใช้สิทธิ์ที่ข้าม RLS จึงอ่านได้ · **ห้ามเติม policy ให้ตารางนี้เด็ดขาด**
- **ห้ามพิมพ์รหัสที่ยังไม่ถูกใช้ของใบอื่นออกมาพร้อมกัน** เวลาออกใบใหม่ — บอกเฉพาะใบที่เพิ่งสร้าง

## ออกรหัสใบใหม่

ตั้งรหัสให้**อ่านออกเสียงได้และไม่กำกวม** เพราะเจ้าของจะส่งให้เพื่อนทางแชตหรือบอกปากเปล่า
— ตัวพิมพ์ใหญ่ล้วน คั่นด้วยขีด **เลี่ยง `0 O 1 I l`** · ถามชื่อคนที่จะให้ก่อนถ้ายังไม่บอก
(ลง `note` ไว้ ไม่งั้นเดือนหน้าจะไม่รู้ว่าใบไหนของใคร)

```sql
insert into public.invite_codes (code, note) values ('<CODE>', '<ให้ใคร>')
returning code, note;
```

อยากให้มีวันหมดอายุก็เติม `expires_at` เช่น `now() + interval '7 days'`

## ดูสถานะ

```sql
select c.code, c.note, c.used_at, u.email as ใช้โดย
  from public.invite_codes c
  left join auth.users u on u.id = c.used_by
 order by c.created_at;
```

รายชื่อผู้ใช้ทั้งหมดพร้อมจำนวนของในระบบ

```sql
select u.email, u.created_at, u.email_confirmed_at is not null as ยืนยันแล้ว,
       (select count(*) from public.areas    a where a.user_id = u.id) as areas,
       (select count(*) from public.projects p where p.user_id = u.id) as projects
  from auth.users u order by u.created_at;
```

> ⚠️ `areas` ต้องเป็น 4 เสมอสำหรับบัญชีที่สมัครผ่านแอป · ถ้าเป็น 0 แปลว่า trigger
> `handle_new_user()` ไม่ทำงาน — **บัญชีนั้นสร้างอะไรไม่ได้เลย** เพราะ `projects.area_id`
> เป็น `not null` · ตรวจว่า trigger ยังอยู่ก่อนออกรหัสใบต่อไป

## เมื่อเจ้าของบอกว่าเทสเสร็จแล้ว อยากลบบัญชีทิ้ง

ลบผ่าน MCP ไม่ได้ (`auth.users` ต้องใช้ Admin API) — **บอกให้เจ้าของกดเอง**
ที่ Dashboard → Authentication → Users → เมนู `...` → Delete user
แล้วบอกว่ารหัสที่บัญชีนั้นใช้จะกลับมาว่างเอง

## ถ้าเจ้าของบอกว่าเมลยืนยันไม่มา

ตามลำดับนี้ ก่อนจะไปไล่หาที่โค้ด

1. Dashboard → Authentication → **Logs** ดูว่าส่งออกไปไหม
2. ตัวส่งเมลที่ Supabase แถมมาจำกัดไม่กี่ฉบับต่อชั่วโมง — เกินแล้วเงียบ ไม่มี error
3. **ทางลัด**: Authentication → Users → บัญชีนั้น → `...` → Confirm email (ยืนยันด้วยมือ)
4. ทางแก้ถาวรคือต่อ SMTP ของตัวเอง (Project Settings → Authentication → SMTP Settings)

## ห้ามทำ

- **ห้ามสร้างผู้ใช้จากปุ่ม Add user ใน dashboard** — มันไม่ส่ง `invite_code` ใน metadata
  แล้ว trigger จะปฏิเสธ · นั่นคือด่านทำงานถูกต้อง ไม่ใช่ของเสีย
  ถ้าจำเป็นจริง ๆ ต้องปิด trigger ชั่วคราว **แล้ว seed Area ให้เองด้วย** (สคริปต์อยู่ใน
  `doc/DECISIONS.md`) — เสนอทางนี้เฉพาะตอนเจ้าของยืนยันว่าสมัครผ่านแอปไม่ได้จริง ๆ
- **ห้ามปิด `Confirm email`** เพื่อให้เทสง่ายขึ้น · ใช้ทางลัดข้อ 3 ข้างบนแทน
