ระบบเดียว สองทางเข้า

ข้อมูลอยู่ที่เดียวบนคลาวด์ แล้วเปิดสองประตูให้เข้าถึง — ประตูที่ คุยได้ กับประตูที่ มองเห็น

ประตูที่คุยได้ คือ Claude ที่ต่อกับฐานข้อมูลผ่าน MCP พิมพ์ว่า “พรุ่งนี้วิชาแคลมี quiz” แล้วมันไปสร้าง reminder ให้ถูกที่เอง ใช้ได้ทั้งบนคอมและในแอปมือถือ เหมาะกับตอนนึกอะไรออกกลางทางแล้วอยากโยนเข้าระบบเร็ว ๆ

ประตูที่มองเห็น คือเว็บแอปที่แสดงทุกอย่างเป็นภาพ — ทั้งแบบรายการและแบบปฏิทิน ติ๊กงานเสร็จ จัดลำดับ แก้ไขได้ครบ เหมาะกับตอนนั่งวางแผนว่าสัปดาห์นี้จะเอายังไง

ทั้งสองประตูอ่านเขียนตารางเดียวกัน ไม่มีการ sync ไม่มีข้อมูลสองชุดที่ต้องมาไล่จับให้ตรงกัน

ระดับบนสองชั้นเป็นแค่ “ที่เก็บ” ของจริงอยู่ชั้นล่างสุดซึ่งแตกเป็นสามชนิด — และ project ยังพ่วง ช่วงเวลาประจำ ได้อีกหลายช่วง สำหรับสิ่งที่เกิดซ้ำตามตาราง เช่นคาบเรียน

ความต่างที่แท้จริงคือ “เวลา”

สามชนิดล่างสุดหน้าตาคล้ายกันมาก ต่างกันที่ฟิลด์เวลาเพียงจุดเดียว — และความต่างนั้นเป็นตัวกำหนดว่าระบบจะปฏิบัติกับมันยังไง

ชนิดฟิลด์เวลาขึ้นปฏิทินระบบทำอะไรให้
taskdue_at (ไม่บังคับ)ขึ้น ถ้ามี due_atขึ้นหน้า “วันนี้” เมื่อใกล้กำหนด · เตือนว่าเลยกำหนด
reminderremind_at *บังคับขึ้นเสมอส่ง push เข้ามือถือเมื่อถึงเวลา ครั้งเดียวจบ
shortnote— ไม่มีไม่ขึ้นเก็บไว้อ่านในหน้า project เท่านั้น
scheduleday + start/end + ช่วงสัปดาห์ขึ้นเสมอวาดเป็นบล็อกในปฏิทิน · ไม่แจ้งเตือน

เก็บ item เป็นตารางเดียวหรือสามตาราง

เสนอให้ใช้ ตารางเดียวชื่อ items แล้วแยกด้วยคอลัมน์ type เพราะทั้งสามชนิดใช้ฟิลด์ร่วมกันเกือบหมด และหน้าจอส่วนใหญ่ต้องดึงมาแสดงปนกันอยู่แล้ว ถ้าแยกสามตารางจะต้อง UNION แทบทุกครั้ง

ป้องกันข้อมูลเพี้ยนด้วย CHECK constraint ที่ระดับฐานข้อมูล เช่น “ถ้า type เป็น reminder แล้ว remind_at ต้องไม่ว่าง” และ “ถ้าเป็น shortnote แล้ว remind_at กับ due_at ต้องว่าง” — กติกาที่ตัว DB บังคับเอง ทำให้ Claude ใส่ข้อมูลผิดรูปไม่ได้ ต่อให้ prompt หลุด

ช่วงเวลาประจำ เก็บยังไงให้รองรับทั้งสองแบบ

คุณต้องการตั้งได้สองแบบ — “ซ้ำไปอีก 16 สัปดาห์” กับ “เลือกเองว่าสัปดาห์ไหนบ้าง” เสนอให้ เก็บเป็นรูปแบบเดียว แต่กรอกได้สองทาง

ในฐานข้อมูลเก็บแค่ start_date กับ week_offsets (รายการเลขสัปดาห์ที่มีคาบ นับจากสัปดาห์แรก) ส่วนโหมด “ซ้ำ 16 สัปดาห์” เป็นแค่ปุ่มลัดใน UI ที่เติม [0,1,2,…,15] ให้เอง

ได้ประโยชน์สองอย่าง — โค้ดวาดปฏิทินมีทางเดียวต้องดูแล และเวลาสัปดาห์ไหนงดคาบ ก็แค่ติ๊กสัปดาห์นั้นออก ไม่ต้องแยกเป็นข้อยกเว้นพิเศษ

ตารางคอลัมน์หลักหมายเหตุ
areas id · user_id · name · color · sort_order วันแรกมี 4 อัน — Class, Hackathon, Financial, Personal
projects id · area_id · name · status · description · sort_order status = active / archived / done — จบเทอมแล้ว archive ทั้งวิชาได้ ไม่ต้องลบ
project_schedules id · project_id · day_of_week · start_time · end_time · location · label · start_date · week_offsets[] หนึ่งแถวต่อหนึ่งช่วงเวลา · หนึ่ง project มีได้หลายแถว (บรรยาย + แล็บ)
items id · project_id · type · title · body · due_at · remind_at · done_at · notified_at · priority task / reminder / shortnote อยู่รวมกันที่นี่ · notified_at กัน push ซ้ำ
push_subscriptions id · user_id · endpoint · p256dh · auth · device_label หนึ่งแถวต่อหนึ่งเครื่องที่กดอนุญาตแจ้งเตือน

ทุกตารางมี user_id และเปิด Row Level Security ตั้งแต่วันแรก แม้จะใช้คนเดียว — เพราะเปิดทีหลังตอนมีข้อมูลแล้วเจ็บกว่ามาก

โครงสร้างสามชั้นเป็นวิธีเก็บ ไม่ใช่วิธีดู — เว็บจึงมีสามมุมมองที่สลับกันได้ตามว่ากำลังจะทำอะไร

การเพิ่มของ มีสองทางที่ไม่เหมือนกัน

ส่วนบน Claude ไม่มีฟอร์มเลย พูดเป็นภาษาคนแล้วมันจัดการเอง แต่ต้อง ทวนกลับมาให้ยืนยันก่อนเสมอ ว่าจะลงที่ไหนเป็นชนิดอะไร เพราะสิ่งที่แย่ที่สุดของระบบแบบนี้คือของหายไปอยู่ผิดที่โดยไม่รู้ตัว

วางฐานข้อมูล

สร้างโปรเจกต์ Supabase, เขียน schema ทั้ง 5 ตาราง, ใส่ CHECK constraint และ RLS, ใส่ข้อมูลจริงของ 4 Area และวิชาที่เรียนอยู่

ได้: ฐานข้อมูลที่ใส่ข้อมูลผิดรูปไม่ได้
เฟส 1

ต่อ Claude เข้ากับฐานข้อมูล

ตั้ง MCP connector, เขียน project prompt ที่อธิบาย schema และกติกา (ยืนยันก่อนเขียน, ห้ามลบโดยไม่ถาม, เดา project จากบริบท, อ่านตารางเวลาเพื่อคำนวณ “คาบหน้า”), ทดสอบทั้งบนคอมและมือถือ

ได้: ใช้งานได้จริงแล้ว — เพิ่ม ลบ ค้นหา ผ่านการพิมพ์คุย

เว็บแอปแบบดูอย่างเดียว

ได้: เห็นภาพรวมทั้งระบบในหน้าจอเดียว

ได้: เห็นตารางเรียนทั้งเทอมโดยกรอกครั้งเดียว

ได้: reminder เด้งเข้ามือถือจริง แม้ปิดเว็บอยู่

ได้: ระบบเริ่มบอกเราแทนที่จะรอเราถาม

เวลาเก็บเป็น UTC เสมอ

ใช้ timestamptz ตลอด แล้วแปลงเป็นเวลาไทยตอนแสดงผล — ยกเว้น start_time/end_time ของตารางเรียนที่ต้องเป็น time เปล่า ๆ เพราะ “09:00 ทุกวันจันทร์” คือเวลาท้องถิ่น ไม่ใช่จุดเวลาจุดเดียว

push ซ้ำเพราะ cron ทับกัน

cron รันทุกนาที ถ้ารอบก่อนยังไม่จบจะเตือนซ้ำ ต้องเขียน notified_at ลงไปในคำสั่งเดียวกับที่เลือกแถว (UPDATE … RETURNING)

service_role key ห้ามหลุดไปฝั่งเว็บ

กุญแจนี้ข้าม RLS ได้ทั้งหมด ให้อยู่แค่ใน Edge Function กับ MCP connector เท่านั้น ฝั่งเบราว์เซอร์ใช้ anon key คู่กับ RLS

Claude ลบของโดยไม่ได้ตั้งใจ

ใน prompt ต้องกำหนดชัดว่าการลบต้องถามยืนยันทุกครั้ง และเสนอให้ใช้ archived_at แทนการลบจริง กู้คืนได้
