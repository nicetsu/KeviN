# DECISIONS — ทุกข้อที่เคาะแล้ว

บันทึกจากการถกวันที่ 17–18 ส.ค. 2026
**อย่าเปลี่ยนข้อไหนโดยไม่ถามเจ้าของก่อน** ทุกข้อผ่านการชั่งน้ำหนักมาแล้ว เหตุผลอยู่ในคอลัมน์ขวา

## สถาปัตยกรรม

| ข้อ | ตัดสิน | เพราะ |
|---|---|---|
| ฐานข้อมูล | Supabase | ต้องอยู่บนคลาวด์เพื่อให้ Claude มือถือเข้าถึงได้ · มี Postgres + RLS + Edge Function + pg_cron ครบในที่เดียว |
| ให้ Claude เข้าถึง | Supabase **remote** MCP (`mcp.supabase.com/mcp`) | เป็น official Claude connector อยู่แล้ว ต่อ OAuth ผ่านเบราว์เซอร์ ไม่ต้อง deploy อะไรเอง · connector ที่เพิ่มจากเว็บใช้ได้ในแอปมือถือด้วย |
| ตัวตั้งเวลาแจ้งเตือน | **pg_cron + Edge Function** ไม่ใช่ Cowork | Vercel Cron แพลนฟรีรันได้วันละครั้ง เตือน "อีก 30 นาที" ไม่ได้ · ส่วน Cowork กิน token ทุกรอบและส่ง push เองไม่ได้ ต้องมายิง Edge Function อยู่ดี · pg_cron รันทุกนาที ฟรี deterministic |
| Cowork เอาไว้ทำอะไร | งานที่ต้องคิด — สรุปเช้า ตรวจงานค้าง | SQL ทำแทนไม่ได้ · วันละครั้งจึงคุ้ม |
| เว็บแอป | Next.js + Vercel | ฟรี ต่อ Supabase ง่าย ทำ PWA ได้ |

## ขอบเขต

| ข้อ | ตัดสิน | เพราะ |
|---|---|---|
| ผู้ใช้ | คนเดียว | แต่ **ใส่ `user_id` ครบทุกตารางและเปิด RLS ตั้งแต่วันแรก** — เปิดทีหลังตอนมีข้อมูลแล้วเจ็บกว่ามาก |
| reminder เตือนซ้ำ | ไม่ทำ เตือนครั้งเดียว | ลดความซับซ้อนมาก · เผื่อคอลัมน์ไว้เติมทีหลังได้ |
| ตารางเรียนประจำสัปดาห์ | **แยกเป็นตาราง `project_schedules`** ไม่ใช่ shortnote | ต้องให้ระบบวาดปฏิทินและคำนวณ "คาบหน้า" ได้ · shortnote เป็นข้อความล้วน ทำไม่ได้ |
| ช่วงเวลาประจำแจ้งเตือนไหม | **ไม่เตือน** แสดงในปฏิทินอย่างเดียว | ถ้าเตือนทุกคาบจะกลายเป็นเสียงรบกวน |
| ปฏิทิน | ดูอย่างเดียว กดดูรายละเอียดได้ แต่ไม่ลากย้าย | ลดงานเยอะ · เพิ่มทีหลังได้โดยไม่ต้องรื้อโครงสร้าง |
| shortnote | รายการธรรมดาในหน้า project **ไม่ปักหมุดบนสุด** | เจ้าของบอกว่าไม่ได้ใช้จดอะไรสำคัญ |
| Areas วันแรก | Class · Hackathon · Financial · **Personal** | ชื่อสุดท้ายเดิมคือ "Project" แต่ชนกับคำว่า project ในระดับที่ 2 — เวลาสั่ง Claude ว่า "เพิ่ม project" จะกำกวมทันที |
| **เปลี่ยนชื่อ Area** (31 ส.ค. 2026) | `Hackathon`→`Competition` · `Financial`→`Personal` · `Personal`→`General` | เจ้าของขอ · **เปลี่ยนชื่อเฉย ๆ ไม่ย้ายอะไร** — `color` เก็บแยกจาก `name` (`class`/`hack`/`fin`/`pers`) gradient จึงไม่กระทบ · ⚠️ ลำดับสำคัญเพราะ `unique(user_id, name)` ต้องปล่อยชื่อ `Personal` ให้ว่างก่อน |

## โครงสร้างข้อมูล

| ข้อ | ตัดสิน | เพราะ |
|---|---|---|
| task/reminder/shortnote | **ตารางเดียว `items`** แยกด้วยคอลัมน์ `type` | ใช้ฟิลด์ร่วมกันเกือบหมด และหน้าจอส่วนใหญ่ต้องดึงมาแสดงปนกัน · ถ้าแยกสามตารางต้อง `UNION` แทบทุกครั้ง |
| กันข้อมูลผิดรูป | `CHECK` constraint ที่ระดับ DB | กติกาที่ DB บังคับเอง ทำให้ Claude ใส่ข้อมูลผิดรูปไม่ได้ **ต่อให้ prompt หลุด** |
| การซ้ำของช่วงเวลาประจำ | เก็บเป็น **`start_date` + `week_offsets int[]`** รูปแบบเดียว | เจ้าของอยากได้สองแบบ — "ซ้ำอีก N สัปดาห์" กับ "เลือกสัปดาห์เอง" · ทำเป็นรูปแบบเดียวแล้วให้ UI มีสองโหมดกรอก โหมด "ซ้ำ N" เป็นแค่ปุ่มลัดที่เติม `[0..N-1]` → โค้ดวาดปฏิทินมีทางเดียวต้องดูแล และงดคาบสัปดาห์ไหนก็แค่ติ๊กออก |
| การลบ | ใช้ `archived_at` แทน `DELETE` | กู้คืนได้ · "ไม่มีอะไรหายเงียบ ๆ" · **แก้ 1 ก.ย. 2026 — ของที่อยู่ในคลังครบ 7 วันถูกลบจริง ดูหัวข้อ "เก็บกวาด" ท้ายไฟล์** |

## UX

| ข้อ | ตัดสิน | เพราะ |
|---|---|---|
| หน้าแรก | มุมมองตามเวลา **ไม่ใช่ลิสต์ Area** | โครงสร้างสามชั้นเป็นวิธีเก็บ ไม่ใช่วิธีดู · ถ้าเปิดมาต้องกดสามทีถึงจะเจองาน จะเลิกใช้ในสองสัปดาห์ |
| หน้าวันนี้แสดงอะไร | ไม่แสดง task ที่ไม่มีวันกำหนด และไม่แสดง shortnote | ถ้าแสดงหมด หน้านี้จะยาวจนไม่ต่างจากคลัง |
| งานที่ติ๊กเสร็จ | ร่วงไปท้ายกลุ่ม ขีดฆ่า จาง **ไม่ซ่อน** | เห็นว่าทำอะไรไปแล้วมีประโยชน์ตอนทบทวน และกันติ๊กผิดแล้วหาไม่เจอ |
| แกนเวลาในปฏิทินสัปดาห์ | คำนวณจากข้อมูลจริง (เร็วสุด −1 ชม. ถึงช้าสุด +1 ชม.) | ไม่ fix 00:00–24:00 ให้ต้องเลื่อนหา |
| **แกนของปฏิทินสัปดาห์** | **วัน = แกนตั้ง · เวลา = แกนนอน** (กลับด้านจาก Google Calendar) | 7 แถวสูงราว 280px ลงจอมือถือได้ครบ **ไม่ต้องตัดเหลือ 3 วัน** · บล็อกวางแนวนอนจึงมีที่พอเขียนชื่อวิชาเต็ม ๆ พร้อมเลขห้อง · แลกกับการเทียบ "สิบโมงของแต่ละวัน" ที่ต้องกวาดตาลง |
| **hero "คาบถัดไป"** | **มองข้ามวันได้ ไม่ใช่แค่วันนี้** (เคาะ 19 ส.ค.) | เดิมดูเฉพาะคาบของวันนี้ พอคาบสุดท้ายเลิก การ์ดหายไปทั้งใบจนถึงเช้าวันรุ่งขึ้น · ช่วงเย็นหลังเลิกเรียนคือตอนที่อยากรู้พอดีว่าพรุ่งนี้เริ่มกี่โมง การ์ดว่างจึงเสียของ · คนละวันไม่ต้องนับถอยหลังเป็นชั่วโมง บอก "พรุ่งนี้ 09:00" ตรง ๆ อ่านง่ายกว่า · มองไปข้างหน้า 14 วันเพื่อให้ข้ามสัปดาห์ที่ไม่มีเรียนได้ |
| S6 ตัวจัดการช่วงเวลา | ต้องมี "ตัวอย่างผลลัพธ์" โชว์วันที่จริง อัปเดตสดขณะพิมพ์ | เป็นตัวจับผิดว่าตั้งค่าผิดตั้งแต่ก่อนกดบันทึก · ถ้ากรอกตารางทั้งเทอมแล้วทรมาน จะไม่มีใครกรอกรอบสอง |

## กิจกรรม (events) — เคาะ 21 ส.ค. 2026

| ข้อ | ตัดสิน | เพราะ |
|---|---|---|
| เก็บที่ไหน | **ตารางใหม่ `events`** ห้อยใต้ Project เป็นพี่น้องกับ `project_schedules` | เส้นแบ่งคือ "ซ้ำหรือไม่ซ้ำ" · `project_schedules` ไม่มีชื่อของตัวเอง (ปฏิทินยืมชื่อ project มาใช้) กิจกรรมหนึ่งอันจึงต้องสร้าง project หนึ่งอัน ซึ่งผิด · ส่วน `week_offsets` เป็นเครื่องมือของการซ้ำ ผิดงานตั้งแต่ต้น |
| `project_id` | **บังคับ** | ทุกตารางในระบบห้อยใต้ Project หมด · ถ้า events ห้อยลอยได้ จะได้ของแถมสามอย่าง — `projects(name)` กลายเป็น nullable ทุก query · ทุก join ต้องเป็น left join · และกฎ "เก็บ project เข้าคลังแล้วของข้างในหายตาม" พังเฉพาะตารางนี้ · เคส "นัดหมอ" ใช้ project "ทั่วไป" ใน General ซึ่ง task ก็ทำแบบนี้อยู่แล้ว |
| กำหนดการภายในงาน | **ตารางที่สี่ `event_agenda`** · ชั้นที่ 4 ของโครงสร้าง | Project UniHack มีหลายงาน (Orientation Day · รับ Booklet · Mentoring · Final Round) และ**แต่ละงานมีกำหนดการของตัวเอง** · ไม่ใช่กรณีที่ Project เป็นตัวคลุมได้ |
| ปฏิทินวาดอะไร | **วาดตัว event ใบเดียว ไม่วาดรายบรรทัดกำหนดการ** | กำหนดการจริงมีบรรทัดสั้นระดับ 10 นาที (Q&A 11:55–12:05) · วาดทุกบรรทัดแล้ววันนั้นจะมีบล็อกจิ๋ว 7 ใบที่ชื่อขาดหมดตั้งแต่บนจอคอม บนมือถือ 375px แย่กว่านั้นอีกเท่าตัว — ปัญหาตระกูลเดียวกับที่ทำให้กลับแกนปฏิทินตั้งแต่แรก · และสัปดาห์ที่มีงานแข่ง คาบเรียนทั้งสัปดาห์จะถูกกลบด้วยรายการย่อยของวันเดียว |
| เวลาในกำหนดการ | `start_time` **บังคับ** · `end_time` **ไม่บังคับ** (เว้นว่าง = ถึงเวลาเริ่มของบรรทัดถัดไป) | กำหนดการ UniHack จริงต่อกันสนิททั้ง 7 บรรทัด เวลาจบจึงเป็นข้อมูลซ้ำ · แต่ถ้าไม่มีที่เก็บเวลาจบเลย ช่องว่างจริง (พักเที่ยงที่ผู้จัดไม่ได้เขียน) จะต้องแทนด้วยบรรทัด "พัก" ปลอม ซึ่งเป็นการบิดข้อมูลให้เข้ากับโครงสร้าง |
| `sort_order` ของ events/agenda | **ไม่มีทั้งคู่** | เรียงตามเวลาได้เสมอ · ถ้าใส่ไว้ ที่จับลากจะโผล่ในที่ที่ลากแล้วเด้งกลับตอนโหลดใหม่ (กับดักเดิมจากเฟส 4) |
| event เตือนเองไหม | **ไม่** · อยากเตือนให้สร้าง `reminder` แยกแล้วผูกด้วย `event_id` | คงกฎเดียวกับ `task_no_remind` ไว้ทั้งระบบ — **มีที่เดียวที่ยิง push คือ `items.type='reminder'`** · ผลคือ `claim_due_reminders()` · Edge Function · pg_cron ไม่ต้องแตะสักบรรทัด |
| event ติ๊กเสร็จได้ไหม | **ไม่มี `done_at`** | เวลาที่ผ่านไปบอกเองว่าจบแล้ว ติ๊กเป็นงานเปล่า |
| ข้ามเที่ยงคืน | **ได้** · `calendar_entries()` หั่นเป็นบล็อกรายวันให้ | งานค้างคืนเป็นเคสจริงของ hackathon · ปฏิทินวางบล็อกด้วย `grid-row = วัน` บล็อกใบหนึ่งจึงอยู่ได้วันเดียว |
| `items.event_id` | **มี แต่ผูกได้จากหน้า event ที่เดียว** | ได้การจัดกลุ่มมาโดยไม่จ่ายค่ากดเพิ่ม · ถ้าถามเรื่อง event ทุกที่ที่สร้างงาน (เพิ่มเร็ว · หน้าวิชา · สั่งผ่าน Claude) จะขัดหลัก UX ข้อ 3 ทันที |
| สีของ event | ~~ใช้ `--sched` ร่วมกับคาบเรียน~~ → **สีของตัวเอง `#D5BB6D` (45°)** · กลับมติหลังเห็นของจริงในเย็นวันเดียวกัน | เหตุผลเดิมคือกลัวว่าสีที่ห้าจะแยกไม่ออกบนบล็อกเล็ก · **แต่พอขึ้นจอจริงปัญหากลับตรงข้าม** คือบนปฏิทินสัปดาห์ที่ทุกอย่างอยู่บนแกนเดียวกัน มองไม่ออกเลยว่าอันไหนคือคาบเรียนที่ต้องไป อันไหนคืองานที่สมัครเอง · ห่างจากส้ม 39° ซึ่งยังกว้างกว่าคู่ที่มีอยู่เดิม (คาบเรียน 187° กับงาน 157° ห่างกันแค่ 30° และอยู่ด้วยกันได้มาตลอด) · **บทเรียน: การตัดสินใจเรื่องสีต้องดูบนจอจริง ไม่ใช่บนกระดาษ** — ซ้ำรอย `--faint` ที่เคาะรอบสองด้วยเหตุผลเดียวกัน |
| หน้า event | **route `/project/[id]/event/[eventId]`** ไม่ใช่ overlay | ขัดกฎ "ลึกเกินสามชั้นให้เปิดทับ" ใน `ux.html` โดยตั้งใจ — กฎนั้นเขียนเพื่อกันการหลงทางตอน**แวะดูเร็ว ๆ** (คือสิ่งที่ S7 ทำ) แต่หน้า event เป็นปลายทางที่มีเนื้อหาของตัวเอง เหมือน S6 ที่เป็น route อยู่แล้ว · **เหตุผลที่หนักที่สุดคือมันมี URL** — Claude สร้าง event ให้แล้วตอบกลับพร้อมลิงก์ให้กดได้ทันที ซึ่ง overlay ทำไม่ได้เลย และ Claude คือประตูอีกครึ่งหนึ่งของระบบ |
| ลิงก์ในเนื้อความ | **ไม่เพิ่มคอลัมน์** · ตรวจ URL/อีเมลใน `body` แล้วทำให้กดได้ตอนแสดงผล | ไม่แตะ schema เลย และได้ผลย้อนหลังกับ `body` ของ task/reminder ทุกแถวทันที · ⚠️ ต้องคืนค่าเป็น element ให้ React escape ให้ **ห้ามใช้ `dangerouslySetInnerHTML`** เพราะข้อความมาจากอีเมลที่ copy มาวาง และ Claude เขียนลง DB ได้ผ่าน MCP |

### การ์ดใหญ่บนหน้าวันนี้

| ข้อ | ตัดสิน | เพราะ |
|---|---|---|
| การ์ดรับ event ด้วย | **ใช่** · "คาบถัดไป" กลายเป็น "ถัดไป" / "กำลังเกิดขึ้น" ตามสถานการณ์ | การ์ดใบนี้มีอยู่แล้ว พอให้มันดู event ด้วย มันรับบทบาทของ "แถบกำลังเกิดขึ้น" ไปเองทั้งหมด — ไม่ต้องสร้างคอมโพเนนต์ใหม่ และรายการข้างล่างไม่ต้องมีกฎพิเศษเลย |
| ชื่อกับเวลา | **ชื่อขึ้นบรรทัดใหญ่ เวลาลงบรรทัดรอง** (สลับจากเดิม) | ทำให้ทุกสถานะใช้โครงเดียวกัน รวมงานข้ามวันที่ไม่มี "เวลาเริ่มของวันนี้" ที่มีความหมาย · แลกกับการที่ตัวเลขเวลาไม่เด่นเท่าเดิม จึงยังใช้ฟอนต์ mono สีตัวอักษรหลัก ไม่ลดเป็นสีจาง |
| บรรทัดล่างของการ์ด | **ช่องเดียว สองความหมาย** — "ถัดไป" ปกติ · "ทับกับ" (สีส้ม) เมื่ออันถัดไปเริ่มก่อนอันบนจบ | มันคือสิ่งเดียวกันคือสิ่งที่จะเริ่มถัดไป ต่างแค่ว่ามันเบียดเข้ามาในเวลาของอันบนหรือไม่ · ไม่ต้องเพิ่มพื้นที่ |
| เอากำหนดการมาโชว์บนการ์ดไหม | **ไม่** | เจ้าของให้เหตุผลว่า **"งานส่วนใหญ่เวลาจริงไม่ค่อยตรงกับกำหนดการอยู่แล้ว"** · กำหนดการคือสิ่งที่ผู้จัดประกาศ ไม่ใช่สิ่งที่เกิดขึ้นจริง · เอาไปโชว์บนการ์ดที่เด่นที่สุดของแอปจะกลายเป็นข้อมูลที่ผิดบ่อยกว่าถูก ในที่ที่ผิดแล้วเสียหายที่สุด |
| อะไรชนะเมื่อเวลาชนกัน | **อันที่เริ่มก่อนชนะ · เริ่มพร้อมกันให้อันที่จบก่อนชนะ** | กฎเดียวใช้ได้ทั้ง event และคาบเรียน ไม่ต้องแยกชนิด และเดาผลได้เสมอ |

### เวลาทับกันและการไม่ไป — ทำแล้ว 21 ส.ค. 2026

เจ้าของชี้ว่าจริง ๆ **ไม่ควรมีอะไรทับกันเลย เพราะไปอยู่สองที่พร้อมกันไม่ได้** · วิธีแก้ของจริงคือตัดทอน
เช่น Orientation 09:00–12:00 กับคาบคณิต 10:00–14:00 ที่ทับกัน ก็ตัดเป็น "อยู่งาน 09:00–11:00 แล้วเข้าคาบ 11:00–14:00"

| ข้อ | ตัดสิน | เพราะ |
|---|---|---|
| เก็บที่ไหน | **ตาราง `time_offsets` แยกต่างหาก** ชี้ไปที่ `schedule_id` หรือ `event_id` + `occurs_on` | ต้องตัด**ทั้งสองฝั่ง** ถ้าตัดข้างเดียวยังทับอยู่ · และคาบเรียนซ้ำทุกสัปดาห์ การไปแก้เวลาในตารางเรียนตรง ๆ จะเปลี่ยนทั้งเทอม |
| แตะเวลาจริงไหม | **ไม่แตะเลย** · คืนค่า = ลบแถวทิ้ง | `project_schedules.start_time` คือเวลาที่มหาลัยกำหนด · `events.starts_at` คือเวลาที่ผู้จัดประกาศ · ทั้งสองอย่างไม่ใช่ของเรา ไม่มีสิทธิ์แก้ |
| **"ไม่ไป" กับ "ไม่มีคาบ"** | **คนละตาราง ห้ามปนกัน** — ไม่ไปลง `time_offsets` · ไม่มีคาบลง `week_offsets` | การลบเลขสัปดาห์เพื่อแทน "ไม่ไป" ให้ผลบนจอที่ถูกต้องเป๊ะ **แต่ทำลายข้อมูลถาวร** — ย้อนดูแล้วแยกไม่ออกว่าหยุดจริงหรือโดด · วิชาที่มีหลายคาบในสัปดาห์เดียวจะหายทั้งหมด · และเลิกทำไม่ได้เพราะไม่มีอะไรบันทึกว่าเลขไหนหายไป |
| ใครเป็นคนตั้งค่า | **Claude ถามแล้วเขียนให้** · เว็บ**ตั้งค่าไม่ได้** ทำได้แค่คืนค่า | เจ้าของสั่งเอง · และตรงกับกฎเดิมที่ว่างานที่ต้องคิดและถามกลับให้ Claude ทำ ส่วนเว็บเก่งเรื่องแสดงภาพ · ผลพลอยได้คือรอบ 2 ไม่ต้องมีหน้าจอตัวแบ่งเวลาเลย เหลือแค่ตาราง ฟังก์ชัน และการแสดงผล |
| ทำไมเว็บยังต้องคืนค่าได้ | หลัก UX ข้อ 5 "ไม่มีอะไรหายเงียบ ๆ" | ถ้าเห็นบนจอว่าคาบถูกตัด ต้องกดคืนได้จากที่เดียวกัน ไม่ต้องเปิดแชต |
| คาบที่ไม่ไป หายจากปฏิทินไหม | **จางอยู่ที่เดิม ไม่หาย** | ถ้าหายไปเลย เปิดปฏิทินมาอีกทีจะไม่รู้ว่าเคยตัดสินใจอะไรไว้ หรือกดผิด · แต่**จุดบนช่องวันในโหมดเดือนไม่นับ** เพราะจุดตอบคำถามว่า "วันนั้นติดอะไรไหม" ซึ่งถ้าไม่ไปแล้วก็คือไม่ติด |
| เวลาที่ใส่อยู่นอกช่วงของคาบ | **เมินแล้วใช้เวลาเดิม** ไม่ปฏิเสธทั้งแถว | ปล่อยผ่านจะได้บล็อกยาวศูนย์หรือกลับหัว แล้วคาบจะหายจากปฏิทินเงียบ ๆ ซึ่งแย่กว่าการที่การตัดไม่มีผล |

| เสียง — กี่ตัวเลือก | **9 แถว** แถวแรกเป็น *ค่าตั้งต้น* ที่แยกตามภาษา | คัดจาก 30 เสียงโดยเน้นโทนเพื่อน + `Charon` เป็นขั้วตรงข้ามไว้เทียบ · ซึ่งกลายเป็นตัวที่เจ้าของเลือกใช้จริงกับภาษาไทย — **เหตุผลที่ต้องใส่ตัวที่โทนต่างเข้าไปในรายการ** |
| ค่าตั้งต้นของเสียง | ไทย `Charon` · อังกฤษ `Fenrir` | ฟังจริงทีละภาษาแล้วเคาะ · เสียงที่เพราะในภาษาหนึ่งไม่ได้แปลว่าเพราะในอีกภาษา |
| ปุ่มฟังตัวอย่างใช้อะไร | **เปิดสาย Live API จริง** ไม่ใช้ TTS | Live ให้เสียงไม่เหมือน TTS · ถ้าให้ฟังจาก TTS ผู้ใช้จะเลือกเสียงจากสิ่งที่ไม่ใช่สิ่งที่ได้ยินตอนโทรจริง — หลอกกันเอง · แลกด้วยการที่กดฟังหนึ่งครั้งกินโควตาเหมือนโทรจริง ซึ่งบอกไว้บนจอแล้ว |
| บันทึกสิ่งที่พูดระหว่างสายไหม | **ไม่บันทึก** ลงเป็น `- voice -` | เจ้าของสั่ง · ที่ยังลงแถวไว้แทนที่จะตัดทิ้ง เพราะยังเห็นจังหวะว่าคุยกี่รอบ ถ้าตัดทิ้งประวัติจะเหลือแต่คำตอบลอย ๆ ที่ไม่รู้ว่าตอบอะไร |
| เปิดให้ผู้ช่วยเห็น Area ไหนบ้าง | **ครบทั้งสี่** | เจ้าของยืนยันว่าไม่มีข้อมูลสำคัญ · **แต่กลไก allowlist ยังอยู่** เพราะประโยชน์ที่แท้จริงคือ Area ที่สร้างใหม่วันหน้าถูกซ่อนไว้ก่อนโดยไม่ต้องมีใครสั่ง |
| ความสูงของหน้า KeviN | **เต็มจอด้วย `dvh`** | `min-height:60vh` เดิมทำให้โหมดโทรจัดกลางของกล่องเตี้ย และช่องพิมพ์ลอยตามเนื้อหา — สองอาการรากเดียวกัน · `vh` ใช้ไม่ได้เพราะไม่หดตามคีย์บอร์ดบนมือถือ |

## เก็บกวาดของที่ผ่านไปแล้ว — เคาะ 1 ก.ย. 2026

เจ้าของถามว่างานที่ผ่านไปแล้วเก็บไว้ไหน คำตอบตอนนั้นคือ **ไม่ไปไหนเลย** —
ไม่มีอะไรพาของเก่าออกจากระบบ และของที่ "ลบ" แล้วก็นอนอยู่ใน DB ตลอดกาล

| ข้อ | ตัดสิน | เพราะ |
|---|---|---|
| reminder ที่ข้ามวันแล้ว | **เก็บเข้าคลังอัตโนมัติ** | หมดหน้าที่ไปแล้ว · push ส่งไปแล้วหรือไม่ก็ตาม |
| task ที่ติ๊กเสร็จแล้ว | **เก็บเข้าคลังเมื่อเลยวันส่งด้วย** ต้องครบทั้งสองข้อ | ติ๊กเสร็จเฉย ๆ ยังอยากเห็นในวันนั้น · **task ที่เสร็จแต่ไม่เคยตั้งวันส่งจะไม่ถูกเก็บ** เพราะไม่มีวันให้เทียบ เจ้าของรับทราบและเลือกแบบนี้เอง |
| task ที่เลยกำหนดแต่ยังไม่เสร็จ | **ไม่แตะ** ค้างหน้าแรกต่อไป | นั่นคือหน้าที่ของมัน |
| **ของในคลังครบ 7 วัน** | **`DELETE` จริง** | **กลับมติ "ลบ = archive"** ที่เขียนไว้ตั้งแต่ออกแบบ schema · เจ้าของเคาะเองหลังเห็นผลกระทบครบ รวมข้อที่ว่า reminder ที่พลาดจะหายถาวรใน 8 วันโดยไม่มีจังหวะให้เห็นอีก |
| ลบครอบคลุมอะไร | `items` · `events` · **และ `projects`** | เจ้าของเลือกให้รวม project เอง ทั้งที่ผมเสนอให้เว้นไว้ · **ลบ project แล้วงานข้างในหายตามทั้งหมด** เพราะ FK เป็น `on delete cascade` ฟังก์ชันจึงนับของที่หายตามแล้วรายงานออกมาเป็นแถวของตัวเอง จะได้ไม่ใช่การหายเงียบ ๆ |
| ไม่แตะ `areas` | ตามที่เจ้าของระบุแค่ project | ลบ area หนึ่งใบเท่ากับล้างทั้งด้าน คนละขนาดกัน |
| รันที่ไหน | **pg_cron เรียก `housekeeping()` ตรง ๆ** ไม่ผ่าน Edge Function | งานนี้ไม่ต้องออกไปข้างนอก ไม่ต้องถือ secret และผลถูกเก็บใน `cron.job_run_details` ให้ย้อนดูได้เอง |
| กิจกรรมที่ผ่านไปแล้ว | **จางลงและร่วงไปท้ายกลุ่ม ไม่ขีดฆ่า** | ขีดฆ่าแปลว่า "จัดการแล้ว" · กิจกรรมที่ผ่านไปไม่ได้แปลว่าใครทำอะไรกับมัน |
| ปุ่มลบของ event | **อยู่ที่แถวเลย** พร้อมแถบเลิกทำ 8 วินาที | เดิมต้องกดลึกสามชั้นถึงจะเจอ ทั้งที่ `archiveEvent` มีอยู่แล้ว |

## Redesign รอบสอง — เคาะ 1 ก.ย. 2026

ตั้งต้นจากการสำรวจว่า "โครงสร้างเปลี่ยนไปแล้วแต่จอยังไม่ตาม" เจอหกจุด
แผนจึงไม่ใช่การทำหน้าจอใหม่เพราะเบื่อของเดิม แต่คือทำให้จอบอกความจริงให้ครบ

| ข้อ | ตัดสิน | เพราะ |
|---|---|---|
| หน้าใหม่ | **`/library/archive` หน้าเดียว** เข้าจากคลัง ไม่ใส่แถบล่าง | เป็นที่ที่แวะนาน ๆ ครั้ง ไม่ใช่ปลายทางประจำวัน |
| เรียงยังไงในหน้านั้น | **ตามเวลาที่เหลือก่อนถูกลบ ไม่ใช่เวลาที่เก็บ** | คำถามที่คนเปิดหน้านี้มาถามคือ "อันไหนกำลังจะหาย" · เรียงตามเวลาที่เก็บจะเอาของที่ปลอดภัยที่สุดขึ้นบนสุด ซึ่งกลับหัวกับคำถาม |
| ปุ่มลบในหน้านั้น | **ไม่มี** | มีสายพานลบอยู่แล้ว การเพิ่มปุ่มลบซ้ำคือการเชิญให้พลาดในหน้าที่ทุกแถวกู้ไม่ได้ถ้าพลาด |
| แยก "ระบบเก็บให้" กับ "กดเก็บเอง" | **เพิ่มคอลัมน์ `archived_auto`** ไม่เดาจากเวลา | cron รันตีสามแต่ผู้ใช้ก็กดเก็บตอนตีสามได้ · การเดาจากนาฬิกาผิดได้โดยไม่มีอะไรฟ้อง — **แตะ schema ต่างจากที่วางแผนไว้ เพราะข้อเท็จจริงนี้เพิ่งเห็นตอนลงมือ** |
| กลุ่ม "พลาดไปแล้ว" ในหน้าวันนี้ | **แยกจาก "เลยกำหนด"** | งานที่เลยกำหนด**ยังทำได้** ส่วนการเตือนที่ผ่านไปแล้ว**ทำอะไรไม่ได้แล้ว** · ปนกันจะทำให้กลุ่มเลยกำหนดยาวขึ้นด้วยของที่กดอะไรไม่ได้ แล้วผู้ใช้จะเลิกอ่านทั้งกลุ่ม |
| ตัวตั้งค่าในหน้า KeviN | **ไม่ย้าย** หน้า `/settings` เป็นที่ที่สองที่ดูค่าได้ | ภาษากับเสียงเป็นของที่อยากปรับ*ระหว่าง*คุย ซึ่งเป็นเหตุผลเดิมที่เอาไปไว้ตรงนั้น · ทั้งสองที่อ่าน `localStorage` ก้อนเดียวกันจึงไม่มีทางไม่ตรงกัน |
| ไลบรารี animation | **ไม่ลงสักตัว** เขียน FLIP เอง 40 บรรทัด | คุมจังหวะให้ตรง token ของโปรเจกต์ได้ และไม่ต้องเพิ่ม 3 kB ให้ PWA ที่ต้องเปิดเร็วบนเน็ตมือถือ |
| การ morph ข้ามหน้า | **ไม่ทำ** ถอดออกหลังพิสูจน์ว่าไม่ติด | ลำดับจริงคือ คลัง → โครงร่าง → หน้าวิชา · ตอนโครงร่างขึ้น ฝั่งเก่าหายไปแล้ว ไม่มีคู่ให้ morph และเบราว์เซอร์ยกเลิก transition ด้วย timeout เพราะทุกหน้าเป็น `force-dynamic` ต้องรอเซิร์ฟเวอร์ · **เลือกเก็บโครงร่างที่ทำงานเสมอ แทน morph ที่ทำงานบางครั้ง** (doc/TRAPS.md) |
| สลับแท็บล่าง | **crossfade ไม่เลื่อนซ้ายขวา** | ห้าแท็บเป็นปลายทางคู่ขนาน ไม่มีอันไหนลึกกว่าอันไหน · เลื่อนจะโกหกว่ามีลำดับ แล้วสมองจะจำโครงสร้างแอปผิด |
| ลำดับการทำ | **หน้าคลังของที่เก็บไว้มาก่อน animation ทั้งหมด** | มันคือช่องว่างที่ทำให้ข้อมูลหายจริง · animation แค่ทำให้ของที่ถูกอยู่แล้วดูดีขึ้น |
