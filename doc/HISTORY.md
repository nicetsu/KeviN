## บทเรียนที่ราคาแพงที่สุด

**ข้อ 1–3 เกิดซ้ำมากกว่าหนึ่งครั้ง** จึงเขียนแยกไว้ — รายละเอียดอยู่ใน `TRAPS.md`

1. **เรื่องสีและขนาดต้องดูบนจอจริงก่อนเคาะ** — `--faint` กลับมติรอบสองหลังใช้บนมือถือ ·
   สีของ event กลับมติในเย็นวันเดียวกันหลังเห็นของจริง · การ์ดคาบถัดไปกับขนาดวันที่
   ก็กลับในวันเดียวกัน · **ภาพเทียบบนจอคอมกับของจริงบนมือถือคือข้อมูลคนละชุด**

2. **ของที่ "ถูกบนจอ ผิดข้างใน และเงียบ" คือศัตรูตัวจริง** — `update` ที่ไม่โดนแถวรายงานว่าสำเร็จ ·
   CHECK ที่ได้ผล NULL ถือว่าผ่าน · ตัวกรอง Area ที่ผูกกับชื่อแล้วชื่อเปลี่ยน ·
   ชนิดใน schema ของ tool ที่ไม่ตรงกับตัวอ่าน · ทุกข้อไม่มี error ให้ใครเห็น

3. **การจูน prompt ต้องวัดก่อนและหลัง** — การแก้ที่ทำให้เคสเป้าหมายผ่านแล้วทำเคสข้างเคียงพัง
   มองไม่เห็นเลยถ้าวัดแต่เคสที่ตั้งใจแก้ · และ **กฎที่มีแต่ "ห้าม" โดยไม่บอกทางเดินต่อ
   จะถูกใช้กว้างเกินเสมอ** — เจอครั้งที่สอง 8 ก.ย. 2026 กับคำว่า "เรียบร้อยแล้ว"
   ที่ห้ามไว้ตั้งแต่ต้นแต่ไม่เคยให้ประโยคไปใช้แทน

4. **ผลจากโมเดลแกว่ง · `n = 3` แยก "ของแกว่ง" ออกจาก "ของถอยหลัง" ไม่ได้** (8 ก.ย. 2026)
   เทียบ prompt เก่า/ใหม่ได้ 3/3 กับ 1/3 แล้วสรุปว่าถอยหลัง · พอทำให้ prompt ฝั่งนั้น
   **เหมือนเดิมทุกตัวอักษร** แล้ววัดซ้ำ เคสเดิมก็ยังตก — คือมันแกว่งเองมาตลอด
   · **ทางที่ถูกคือทำให้ตัวแปรที่สงสัยเป็นศูนย์แล้ววัดซ้ำ ไม่ใช่ยิงเพิ่มไปเรื่อย ๆ**

---

5. **"เสร็จ" ของงานที่พังแล้วเงียบ ต้องรวมการยิงขาที่ถูกด้วย** (9 ก.ย. 2026)
   ด่านของ `send-reminders` รอบแรกกัน**ทุกคน**รวมทั้ง cron เอง เพราะ service_role key
   มีสองรุ่นที่ไม่ใช่ค่าเดียวกัน · ถ้าเทสต์แค่ "ยิงมั่วแล้วโดนปฏิเสธ" มันผ่านสวยงาม
   แล้วการเตือนก็หยุดส่งไปเงียบ ๆ · **ของที่ล้มไปทางปลอดภัยยังต้องพิสูจน์ว่ามันไม่ได้ล้ม**

6. **เคสวัดที่วัดสองเรื่องพร้อมกัน ตกแล้วบอกอะไรไม่ได้ — เจอครั้งที่สอง** (9 ก.ย. 2026)
   เคส 24 ฉบับแรกวัดทั้ง "ไม่เดา" และ "ไล่ชื่อตัวเลือกให้" · ฝั่งแชตถามกลับถูกต้อง
   แต่ตกเพราะไม่ได้ไล่ชื่อ ส่วนฝั่งโทรไล่ชื่อจนผ่าน — **ตัวเลขอ่านเหมือนแชตแย่กว่าโทร
   ทั้งที่ทั้งคู่ทำสิ่งที่สำคัญถูกเหมือนกัน** · บทเรียนเดียวกับเคส 20 เมื่อ 8 ก.ย.

## หลักการ UX ห้าข้อ (ใช้ตัดสินทุกครั้งที่ลังเล)

1. เปิดมาต้องตอบได้ทันทีว่าตอนนี้ต้องทำอะไร — โครงสร้างสามชั้นเป็นวิธีเก็บ ไม่ใช่วิธีดู
2. สีมีความหมายเดียว ใช้ตรงกันทั้งระบบ ไม่มีสีไหนใช้เพื่อความสวย
3. งานที่ทำบ่อยต้องกดน้อยที่สุด
4. ปฏิทินไว้ดู คลังไว้แก้ — ไม่พยายามให้ทุกหน้าทำได้ทุกอย่าง
5. **ไม่มีอะไรหายเงียบ ๆ** — ลบต้องยืนยัน · archive กู้คืนได้ · ผู้ช่วยเขียนอะไรต้องบอก
