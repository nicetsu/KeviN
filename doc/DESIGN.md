## กฎข้อเดียวที่ทุกอย่างตามมา

องศาที่กำกับคือระยะบนวงล้อสี — ม่วงอยู่ที่ 265° ทุกสีห่างออกไปอย่างน้อย 78° จึงแยกออกได้แม้บนบล็อกเล็ก ๆ ในปฏิทิน

**ทำไมกิจกรรมต้องมีสีของตัวเอง** (เพิ่ม 21 ส.ค. 2026)
รอบแรกให้กิจกรรมใช้ `#79C2D0` ร่วมกับคาบเรียน แล้วนิยามความหมายใหม่เป็น "ช่วงเวลาที่ถูกจองไว้"
ด้วยเหตุผลว่าไม่อยากให้สีเยอะจนแยกไม่ออกบนบล็อกเล็ก · **แต่พอขึ้นจอจริงปัญหากลับตรงข้าม** —
บนปฏิทินสัปดาห์ที่ทุกอย่างอยู่บนแกนเดียวกัน มองไม่ออกเลยว่าบล็อกไหนคือคาบเรียนที่ต้องไป
กับบล็อกไหนคืองานที่สมัครเอง ซึ่งเป็นข้อมูลคนละชั้นกัน

กิจกรรมอยู่ที่ 45° ห่างจากส้ม (เส้นตาย) 39° ซึ่งใกล้กว่าคู่อื่น แต่ยังกว้างกว่าคู่ที่มีอยู่เดิม
คือคาบเรียน 187° กับงาน 157° ที่ห่างกันแค่ 30° และอยู่ด้วยกันได้มาตลอด

## จังหวะการเคลื่อนไหว

ค่าเดียวใช้ทั้งแอป — animation ที่ความเร็วไม่เท่ากันคือสิ่งที่ทำให้รู้สึกไม่เนียน

| token | ค่า | ใช้กับ |
|---|---|---|
| `--t-fast` | 140ms | ตอบสนองการแตะ · ติ๊ก · ปุ่มยุบ |
| `--t-base` | 220ms | แผงเปิดปิด · แถวเข้าออก |
| `--t-slow` | 320ms | เปลี่ยนหน้า · morph ข้ามหน้า |
| `--ease` | `cubic-bezier(.22,.61,.36,1)` | ทุกอย่าง · ออกตัวเร็ว จบช้า |

> **ไม่มีอะไรเกิน 320ms** เกินกว่านั้นคนเริ่มรู้สึกว่า "รอ" แทนที่จะรู้สึกว่า "ลื่น"
> และแอปที่ใช้ทุกวันต้องเร็วกว่าแอปที่เปิดดูครั้งเดียว
>
> ⚠️ **ทุก `@keyframes` และ `transition` ใหม่ต้องมี `@media (prefers-reduced-motion: reduce)` คุม**
> ของเดิมทำครบทุกตัว อย่าให้ของใหม่เป็นตัวแรกที่ทำพัง

## ตัวอักษร

## ปฏิทินสัปดาห์ — โครงที่กลับด้าน

**วัน = แกนตั้ง · เวลา = แกนนอน** (ไม่ใช่แบบ Google Calendar)

```css
.wk { display: grid; grid-template-columns: 2.9rem repeat(12, minmax(40px, 1fr)); grid-auto-rows: 40px; }
/* คาบวันจันทร์ 09:00–11:00 → แถว 2 (จันทร์), คอลัมน์ 3 (09:00) ยาว 2 ช่อง */
.blk { grid-row: 2; grid-column: 3 / span 2; }
```

- แถว 1 = หัวตารางเวลา · แถว 2–8 = จันทร์ถึงอาทิตย์
- คอลัมน์ 1 = ชื่อวัน · คอลัมน์ 2+ = ช่องละ 1 ชั่วโมง
- เส้นเวลาปัจจุบันเป็น**เส้นแนวตั้ง** สีแบรนด์
- บล็อกซ้อนกัน → **แบ่งความสูงในแถวของวันนั้น**
- ช่วงเวลาที่แสดง คำนวณจากคาบเร็วสุด −1 ชม. ถึงช้าสุด +1 ชม.

ได้อะไร: 7 แถวสูงราว 280px ลงจอมือถือได้ครบ ไม่ต้องตัดเหลือ 3 วัน · บล็อกวางแนวนอนจึงมีที่พอเขียนชื่อวิชาเต็มพร้อมเลขห้อง

## สถานะการออกแบบ

**ครบทุกหน้าแล้ว** — `ux.html` ถูกทาสีใหม่เป็น Nightfall เมื่อ 18 ส.ค. 2026
มีเฟรมครบ S1–S9 (บวก S3 เวอร์ชันมือถือ) พร้อมกฎการแสดงผล และสถานะพิเศษอีก 6 แบบ
(วันนี้ว่าง · คลังว่าง · สัปดาห์ว่าง · ออฟไลน์ · บันทึกไม่สำเร็จ · กำลังโหลด)

สิ่งที่แก้ตอนทาสีใหม่ นอกจากจานสี:

- **แยก `--brand` ออกจาก `--task`** — เดิมตัวแปรเดียวทำสองหน้าที่ คือทั้งสี UI ที่กดได้
  และสี "งานทั่วไป" ถ้าสลับจานสีเฉย ๆ การ์ดงานจะกลายเป็นม่วงทั้งหมด ขัดกฎข้อเดียวของสไตล์นี้
- **แก้บั๊กสีของ reminder** — เดิมถูกระบายด้วยสีแบรนด์ทั้งในปฏิทินเดือน ปฏิทินสัปดาห์
  และแถบ legend ทั้งที่กฎในเอกสารเองบอกว่า reminder ต้องใช้สีเส้นตาย
- **ยุบธีมสว่างทิ้ง** — เหลือจานเดียว ตาม DECISIONS.md ที่เคาะว่ามืดอย่างเดียว
- **ปิดเงา** (`--shadow: none`) ตามกฎ "ไม่มีเงาตอนนิ่ง"

## เคาะแล้ว · คอนทราสต์ของ `--faint`

ค่าเดิม `#6E6B83` **ตกเกณฑ์ WCAG AA ทุกพื้นหลัง** — 3.86 บน `--paper` · 3.58 บน `--surface` · 3.30 บน `--sunk`
(เกณฑ์ 4.5) เป็นจุดเดียวในระบบที่ตก ส่วนตัวอักษรหลักได้ 17.5

**เคาะสองรอบ:**

| เมื่อไหร่ | ผล | เพราะ |
|---|---|---|
| 18 ส.ค. 2026 | คง `#6E6B83` | ดูจากภาพเทียบบนจอคอมแล้วชอบความสงบของค่าเดิม |
| **19 ส.ค. 2026** | **เปลี่ยนเป็น `#87849D`** | **หลังใช้งานจริงบนมือถือ** เจ้าของเลือกค่าที่อ่านง่ายกว่า |

รอบแรกตัดสินจากภาพบนจอคอม รอบสองตัดสินหลังเปิดใช้จริง — ข้อมูลคนละชุดกัน ผลเลยต่างกัน

`#87849D` คือค่าที่ขยับน้อยที่สุดแล้วผ่านทุกพื้น (4.69 บนพื้นแย่สุด) คงเฉดเดิมไว้ แค่สว่างขึ้น
และยังห่างจาก `--muted` (`#A5A2B8`) พอให้ลำดับความสำคัญยังอ่านออก

---|---|---|
| `--paper` | 3.86 | 4.5 |
| `--surface` | 3.58 | 4.5 |
| `--sunk` | 3.30 | 4.5 |

เป็นจุดเดียวในทั้งไฟล์ที่ตก — ที่เหลือผ่านหมด (ตัวอักษรหลักได้ 17.5)

แต่มันคือสีของบรรทัดข้อมูลตัวเล็ก 9–13px ซึ่งก็คือชื่อ project เลขห้อง และเวลา —
**ข้อมูลที่ต้องอ่านตอนเดินไปเรียนกลางแดด** ซึ่งเป็นเหตุผลที่เลือกดันคอนทราสต์สูงตั้งแต่แรก

**เจ้าของเคาะเมื่อ 18 ส.ค. 2026: คง `#6E6B83` ไว้เหมือนเดิม**

เสนอ `#87849D` (ผ่าน AA ทุกพื้น) และ `#918EA6` ไปแล้ว พร้อมตัวอย่างเทียบกันของจริง
เจ้าของเลือกค่าเดิมหลังเห็นภาพเทียบ — ยอมแลกคะแนนคอนทราสต์กับความสงบของหน้าจอ
และลำดับความสำคัญที่ชัดกว่า (ระยะห่างระหว่าง `--faint` กับ `--muted` ยังกว้าง)

> ⚠️ **อย่าเปลี่ยนค่านี้เองในอนาคต** ถ้าเครื่องมือตรวจ accessibility ทักขึ้นมา
