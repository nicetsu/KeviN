04การซ้ำของตารางเรียน

เก็บเป็นรูปแบบเดียว ไม่ว่าผู้ใช้จะกรอกด้วยโหมดไหน

start_date    = วันจันทร์ของสัปดาห์ที่ 0
week_offsets  = [0,1,2,...] สัปดาห์ที่มีคาบนี้

โหมด ก  "ซ้ำอีก 17 สัปดาห์"  →  [0,1,2,...,16]
โหมด ข  "เลือกสัปดาห์เอง"    →  [0,2,4,6]  (เช่นแล็บสลับสัปดาห์)

โหมด ก เป็นแค่ปุ่มลัดที่เติม [0..N-1] — ลง DB เหมือนกันทั้งคู่ ทำให้ไม่มีตรรกะแยกสองทางให้ต้องดูแล

start_time / end_time เป็น time เปล่า ไม่ใช่ timestamptz โดยตั้งใจ — "09:00 ทุกวันจันทร์" คือเวลาท้องถิ่น ไม่ใช่จุดเวลาจุดเดียวบนไทม์ไลน์

คลี่ออกเป็นวันที่จริง

schedule_occurrences(from, to) เป็นตัวเดียวที่ทำหน้าที่นี้ — ทุกที่ที่ต้องรู้ว่าคาบไหนตกวันไหนต้องเรียกตัวนี้ ห้ามคำนวณเอง

ยกเว้นที่เดียวคือ web/lib/weeks.ts ซึ่งคำนวณแบบเดียวกันฝั่งเบราว์เซอร์ เพื่อโชว์ "ตัวอย่างสด" ขณะกรอกฟอร์ม — และมีเทสต์เทียบกับผลจาก DB จริงว่าตรงกัน ถ้าแก้ตัวใดตัวหนึ่งต้องแก้อีกตัวด้วย

05กิจกรรมและการตัดทอนเวลา

สองอย่างที่ตารางเรียนอย่างเดียวเก็บไม่ได้ — งานที่เกิดครั้งเดียว และคำตัดสินว่าจริง ๆ แล้วจะไปหรือไม่ไป

ทำไม project_schedules ไม่พอ

มันไม่มีชื่อของตัวเอง — ปฏิทินยืมชื่อ project มาใช้ ดังนั้นกิจกรรมหนึ่งอันจะต้องสร้าง project หนึ่งอัน · และ week_offsets เป็นเครื่องมือของ "การซ้ำ" ซึ่งผิดงาน ตั้งแต่ต้นสำหรับสิ่งที่เกิดครั้งเดียว

calendar_entries() — ประตูเดียวของปฏิทิน

รวม คาบเรียน + กิจกรรม เป็นรูปเดียว และเอาการตัดทอนมาใช้ให้แล้ว · security invoker จึงเคารพ RLS เหมือน schedule_occurrences()

มีสามที่ที่กินข้อมูลชุดนี้ — การ์ดใหญ่หน้าแรก · ปฏิทินเดือน · ปฏิทินสัปดาห์ ถ้ารวมฝั่งเว็บต้องเขียนตรรกะเดียวกันสามรอบ ห้ามดึง events มาปนเองฝั่งเว็บ

คืนสองคอลัมน์ที่ฝั่งเว็บต้องอ่าน — skipped (ตั้งใจไม่ไป) และ trimmed (เวลาถูกตัด) · แถวที่ skipped ยังอยู่ในผลลัพธ์ ไม่ถูกกรองทิ้ง เว็บทำให้จางลงและติดป้ายแทนการซ่อน

กิจกรรมข้ามคืนถูกหั่นเป็นบล็อกรายวัน

ปฏิทินสัปดาห์วางบล็อกด้วย grid-row = วัน บล็อกใบหนึ่งจึงอยู่ได้วันเดียว

ศุกร์ 20:00 → เสาร์ 09:00

  กลายเป็น   ศุกร์ 20:00–24:00   +   เสาร์ 00:00–09:00
"24:00:00" ประกอบเป็น Date ไม่ได้
new Date('2026-09-05T24:00:00+07:00') คืน Invalid Date เงียบ ๆ ไม่ throw
ต้องแปลงเป็นเที่ยงคืนของวันถัดไปเอง — ทำไว้แล้วใน entryEndMs() ที่ web/lib/calendar.ts ห้ามคำนวณเองที่อื่น

time_offsets — คำตัดสินของเจ้าของ แยกจากเวลาจริง

เวลาชุดไหนเก็บที่ใครเป็นเจ้าของ
คาบเรียนproject_schedules.start_timeมหาลัยกำหนด
กิจกรรมevents.starts_atผู้จัดประกาศ
จะไปไหม ถึงกี่โมงtime_offsetsเจ้าของ · เฉพาะวันนั้น

คืนค่า = ลบแถวทิ้ง · เวลาจริงไม่เคยถูกแตะเลยตั้งแต่ต้น

week_offsets ไม่ใช่ที่เก็บ "ฉันจะไม่ไป"
มันแปลว่า สัปดาห์นั้นมหาลัยไม่มีคาบ (สัปดาห์สอบ · Commencement Week)
การเอาไปใช้แทนความหมาย "ไม่ไป" ให้ผลบนปฏิทินที่ถูกต้องเป๊ะ แต่ทำลายข้อมูลถาวร — ย้อนดูแล้วแยกไม่ออกว่าหยุดจริงหรือโดด · วิชาที่มีหลายคาบในสัปดาห์เดียวจะหายทั้งหมด · และเลิกทำไม่ได้เพราะไม่มีอะไรบันทึกว่าเลขไหนหายไป

ใครเป็นคนตั้งค่าตัดทอน

Claude ถามแล้วเขียนให้ — เว็บตั้งค่าไม่ได้โดยตั้งใจ ทำได้แค่กดคืนค่า · การถามว่า "จะแบ่งเวลาตรงไหน" แล้วรอคำตอบคือบทสนทนา ไม่ใช่ฟอร์ม ซึ่งตรงกับกฎเดิมที่ว่างานที่ต้องคิดให้ Claude ทำ ส่วนเว็บเก่งเรื่องแสดงภาพ

แต่การคืนค่าต้องมีบนเว็บ เพราะหลัก UX ข้อ 5 "ไม่มีอะไรหายเงียบ ๆ" — ถ้าเห็นบนจอว่าคาบถูกตัด ต้องกดคืนได้จากที่เดียวกัน

06เส้นทางแจ้งเตือน

ทำไมต้องเช็ก "มีเครื่องรับไหม" ก่อนอ้างสิทธิ์
claim_due_reminders() เขียน notified_at ทันทีที่หยิบแถว ถ้าหยิบมาแล้วไม่มีที่ส่ง การเตือนจะถูกทำเครื่องหมายว่าส่งแล้วและหายไปเงียบ ๆ
เคยเกิดขึ้นจริงตอนทดสอบครั้งแรก — reminder 3 ตัวถูกเผาทิ้งโดยไม่มีอะไรเด้ง

ทำไมต้องอ้างสิทธิ์แบบ atomic

update items set notified_at = now()
 where type='reminder' and notified_at is null and remind_at <= now()
returning *;

cron รันทุกนาที ถ้ารอบก่อนยังไม่จบจะเตือนซ้ำ — การเขียน notified_at ลงไปในคำสั่งเดียวกับที่เลือกแถว ทำให้อ้างสิทธิ์ได้แค่รอบเดียว ห้ามแยกเป็น SELECT แล้วค่อย UPDATE เด็ดขาด
